# 연구 수행 규범 (Research Protocol) v3.0

> **목적:** 연구 질문과 방향에 따라 탐색하고, 그 결과로 다음 접근을 판단하며 지식을 축적한다. 탐색 결과·성능 주장·기전 설명을 구분한다.
> **적용:** 실험·계산 연구와 이를 수행하는 인간·AI 에이전트의 공통 기본 규범이다. 이론·정성·관찰 연구는 연구 질문에 맞는 증거와 절차로 구체화한다. 모든 연구에 같은 통계 검정이나 코드 변경을 요구하지 않는다.
> **운영:** 채택한 프로젝트에서 적용한다. 사용자 지시, 안전 규칙, 실행 환경의 권한 체계를 우선한다. 프로젝트 규범은 적용 범위·예산·평가 설계·위임 범위를 명시한다. 이 문서 자체가 외부 시스템의 지시 우선순위를 바꾸지는 않는다.
> **근거와 한계:** ICF 회고에서 출발한 방법론적 제안이다. 연구 성공이나 모든 분야에서의 유효성을 보장하지 않는다. 사례의 근거 수준은 §9에 명시한다.

## 1. 차단할 실패 양식과 핵심 원칙

### 양식 A — 학습 없는 반복

후보를 구현하고 지표를 본 뒤, 무엇을 알게 되었는지 남기지 않고 다음 후보로 넘어간다. 같은 접근을 이름만 바꿔 반복하거나, 왜 재시도하는지 설명하지 못하는 것이 징후다.

### 양식 B — 연구 방향 없이 주어진 조합의 수치만 최대화

무엇이 현재 접근의 한계인지, 어떤 가능성을 찾아볼지, 왜 그 후보 범위를 살피는지 정하지 않은 채 주어진 구성과 조합에서 높은 점수만 찾는다. 후보를 많이 실행해도 문제의 구조나 다른 접근의 가능성을 알아가는 탐색이 없으면 연구 방향은 생기지 않는다. “높으면 채택, 낮으면 다음 조합”만으로는 무엇을 배웠고 왜 다음 시도를 해야 하는지 설명할 수 없다.

탐색은 처음부터 정답이나 기전을 아는 것을 요구하지 않는다. 방향 자체가 불명확하면 한계·오류 양상·가능한 접근을 조사해 방향을 찾는 것이 탐색의 질문이 될 수 있다. 다만 범위·예산·선택 규칙을 적거나 작업을 `exploratory`라고 부르는 것만으로 이 요건을 충족하지는 않는다.

성능 최적화는 명시된 연구 방향이나 운영 목적의 수단으로 수행할 수 있다. 그 경우 왜 이 범위를 최적화하는지와 완료 조건을 밝히고, 확보한 구성·점수와 새로 알아낸 사실을 구분한다. 유효한 독립 평가로 점수 향상을 확인하더라도 그것만으로 연구 방향의 부재가 해결되지는 않는다.

### 양식 C — 선택 결과를 확증으로 포장

많은 구성·시점·지표를 살핀 뒤 가장 유리한 결과를 고르고, 그 선택에 쓰인 자료로 다시 성공을 선언한다. 불리한 결과나 사후 기준 변경을 숨기면 판정의 의미가 사라진다.

### 지켜야 할 원칙

1. **연구 방향·질문·증거를 연결한다.** 해결할 문제나 탐색할 가능성, 후보 범위를 택한 이유, 결과가 다음 접근을 판단하는 데 무엇을 알려줄지 밝힌다. “점수를 높인다”만으로 연구 질문을 대신하지 않는다.
2. **모르는 기전을 꾸며내지 않는다.** 탐색을 허용하되 성능 관측을 기전의 입증으로 바꾸어 쓰지 않는다.
3. **기준과 선택 이력을 드러낸다.** 탐색과 확증을 구분하고 결과를 보고 바꾼 기준을 표시한다.
4. **결론은 증거의 범위를 넘지 않는다.** 실패·반박·판별 불가·실행 무효를 구분한다.
5. **비용을 제한하고 지식을 남긴다.** 원인 미상도 정직하게 기록한 뒤 보류할 수 있다.

## 2. 연구 경로 — 질문에 필요한 단계만 수행한다

### 2.1 RU 유형

연구 단위(RU)는 하나의 질문을 중심으로 묶는다. 관련된 여러 실행을 포함할 수 있다. 커밋 수나 실행 횟수는 연구 진척의 대리 지표가 아니다.

| 유형 | 목적 | 기본 경로 | 종료 산출물 |
|:---|:---|:---|:---|
| `exploratory` 탐색 | 패턴·후보·가설 발견 | 질문 → 제한된 탐색 → 후보/불확실성 정리 | 탐색 범위, 선택 이력, 후속 질문 |
| `diagnostic` 진단 | 경쟁 설명 구별, 원인 조사 | 관찰 → 설명 후보 → 구별 가능한 측정/개입 → 해석 | 각 설명을 지지·약화하는 증거와 한계 |
| `confirmatory` 확증 | 명시한 주장의 평가 | 주장·설계 고정 → 실행 → 사전 규칙 판정 | 효과·불확실성·적용 범위·회귀 |
| `reproduction_measurement` 재현·계측 | 기존 결과 재현, 측정 신뢰성·정밀도 확보 | 대상·기대 동작 정의 → 재실행/교차 점검 → 차이 분석 | 재현 범위, 오차·결함·미확인 사항 |

탐색에는 기전 가설이 없어도 된다. 그러나 무엇을 발견하려는지, 왜 이 범위와 후보를 살피는지, 결과가 후속 방향에 무엇을 알려줄지는 밝힌다. 성능 후보 탐색에도 이 질문과 함께 범위·예산·선택 규칙을 기록한다. 후보 순위표만을 연구 지식의 축적으로 간주하지 않는다. 유형을 바꾸면 전환 시점과 이미 본 자료를 기록하며, 과거 탐색을 소급해 확증이라고 부르지 않는다.

### 2.2 기전 기반 개선의 권장 사슬

`관찰 → 기전 가설 → 진단 → 처방 → 검증`은 원인을 설명하며 시스템을 개선하려는 연구에 적합하다. 각 단계를 별도 RU로 수행하거나 기존 증거를 링크해 충족할 수 있다.

| 단계 | 요구 사항 | 다음 단계로 갈 근거 |
|:---|:---|:---|
| 관찰 | 수치·조건·출처·재현 상태 기록 | 현상이 실제인지 평가할 증거가 있다. 단회 관측은 단회라고 표시한다. |
| 기전 가설 | 적용 조건, 예상 관측, 경쟁 설명, 반박할 관측 | 설명들을 구별할 수 있는 예측이 있다. |
| 진단 | 수동 계측 또는 통제된 절제·섭동 | 조작이 의도대로 작동했는지와 결과의 대안 설명을 점검했다. |
| 처방 | 진단과 연결되는 최소한의 일관된 변경 | 변경의 목적과 예상 효과를 설명할 수 있다. |
| 검증 | 사전 기준과 평가 설계로 결과·회귀 평가 | 성능 주장과 기전 주장을 각각 판정한다. |

진단용 코드 작성은 허용된다. 진단 여부는 임시 코드인지보다 **무엇을 구별하도록 설계했는지**로 판단한다. 기준선과 프로브 구성을 분리하고 복원 가능하게 보존한다.

기전 진단에 성능 지표를 사용할 수도 있다. 핵심은 특정 지표를 배제하는 것이 아니라, 관측이 경쟁 설명을 얼마나 구별하는지다. 상관·출력 분산·유효 랭크 등은 기전의 단서가 될 수 있으나 단독으로 인과성을 보장하지 않는다.

처방이 실패했다고 기전이 자동으로 반박되지는 않는다. 조작 실패, 계측 문제, 낮은 검정력, 상쇄 효과를 확인한다. 반대로 기전이 불명확해도 유효한 평가로 경험적 성능 우위를 주장할 수 있다. 그 경우 **기전 미확인**을 함께 적는다.

## 3. RU 카드와 종료 규칙

### 3.1 착수 전 최소 기록

다음 내용을 짧게 기록한다. 적용되지 않는 필드는 `해당 없음: 이유`로 적고, 미정 사항은 이를 정할 탐색 RU로 분리한다. 일상적인 문서 수정이나 결과 해석에 영향 없는 코드 정리에 별도 RU를 강제하지 않는다.

| 필드 | 내용 |
|:---|:---|
| `id`, `type` | 식별자와 §2.1 유형 |
| `question`, `value` | 해결할 문제·탐색할 가능성, 줄일 불확실성, 후속 연구 방향 또는 운영 결정과의 연결 |
| `claim_or_hypothesis` | 확증 주장의 범위 또는 진단의 경쟁 설명. 탐색은 `미정` 허용 |
| `design` | 탐색 범위·후보를 택한 이유, 데이터·비교군·표집/반복 단위·측정 방법·고정 조건 |
| `criteria` | 판정 또는 탐색 완료 기준, 불확실성 처리, 회귀 허용치 |
| `budget`, `stop` | 시간·계산·실행 상한 및 조기 중단 조건 |
| `next_actions` | 예상 결과별 행동, 판별 불가·실행 무효 처리 |
| `provenance` | 규범·코드·설정·데이터 버전 및 이미 본 평가 자료 |
| `closed_axes_check` | 관련 축 기록과의 대조 결과 또는 해당 없음 |

통과·실패 후 당장 수행할 작업이 같아도 재현, 감사, 추정 정밀도 향상은 가치가 있다. 다만 결과가 어떤 지식이나 판단에 쓰이는지 설명하지 못한다면 착수 필요성을 재검토한다.

### 3.2 복사해서 쓰는 예시

아래 수치와 조건은 **가상의 작성 예시**이며 공통 권장값이 아니다. 실제 실행 전에 해당 프로젝트의 계획으로 바꾼다.

```yaml
id: RU-EXAMPLE-01
type: exploratory
question: 특정 입력 길이 구간의 오차 증가가 어떤 패턴을 보이는가?
value: 다음 진단의 우선순위를 정한다.
claim_or_hypothesis: 미정 — 패턴 탐색 후 경쟁 설명을 작성한다.
design:
  data: 개발용 데이터 v1; 최종 평가셋 접근 없음
  method: 길이 구간별 오차·표본 수·원시 출력 점검
  sampling_unit: 문서; 동일 문서 내 관측의 의존성을 보존
criteria: 사전 정의한 모든 구간의 집계와 빈 구간을 보고하고 대표 오류를 확인
budget: 작업 2시간, 집계 실행 최대 3회
stop: 예산 소진 또는 집계 불일치 발견 시 원인 기록 후 종료
next_actions:
  pattern_found: 경쟁 설명과 구별 가능한 진단을 작성
  no_clear_pattern: 탐색 범위와 판별 한계 기록 후 우선순위 재평가
  invalid: 계측 수정 작업으로 전환
provenance: 실행 전 코드·설정·데이터 버전과 자료 접근 이력 기록
closed_axes_check: 관련 기록 없음 — 착수 전 다시 대조
```

```yaml
id: RU-EXAMPLE-02
type: confirmatory
question: 고정한 후보가 목표 분포에서 기준선보다 실용적으로 우수한가?
value: 후보의 채택 여부를 결정한다.
claim_or_hypothesis: 지정된 목표 분포에서 평균 정확도 차이가 0.01을 초과한다.
design:
  metric: 후보 정확도 - 기준선 정확도; 0.01은 1퍼센트포인트
  comparison: 동일 평가 문서에서 두 고정 모델을 대응 비교
  sampling_unit: 독립 문서; 문서 내 항목은 묶어서 처리
  data: 선택에 사용하지 않은 평가 자료; 계획 고정 후 공개
  uncertainty: 문서 단위 대응 bootstrap, 사전 고정한 95% 구간
  scope: 고정된 두 모델의 목표 분포 성능; 재학습 변동과 OOD는 별도
criteria:
  support: 효과 구간의 하한 > 0.01, 회귀 제약 충족
  against: 효과 구간의 상한 <= 0.01
  inconclusive: 효과 구간이 0.01을 걸침
  regression: 사전 정의한 처리시간 예산 충족; 모든 측정 지표 변화 보고
budget: 고정 평가 1회와 사전 계획한 재표집 계산; 총 2시간
stop: 누수·평가 구현 오류 시 실행 무효; 중간 점수에 따른 표본 추가 금지
next_actions:
  support: 승인된 범위에서 채택하고 기전 미확인을 명시
  against: 이번 성능 주장 반박 기록; 기전 반증으로 해석하지 않음
  inconclusive: 채택 보류, 추가 정보의 가치와 비용 검토
  invalid: 원인 수정 후 새 평가 계획 수립
provenance: 실행 전 모델 해시·데이터 버전·계획 시점·분석 설정 고정
closed_axes_check: 관련 축과 재개 조건 충족 여부를 기록
```

### 3.3 종료 시 두 종류의 판정을 분리한다

**증거 판정:** `지지 / 반박 / 판별 불가 / 실행 무효`. 탐색에는 `탐색 완료`를 사용할 수 있으며 이는 발견한 가설의 확증이 아니다.

**운영 결정:** `채택 / 추가 진단 / 보류 / 종료`. 예산 때문에 종료하더라도 증거 판정은 판별 불가일 수 있다. 효과가 지지되어도 비용·회귀 제약 때문에 채택하지 않을 수 있다.

종료 기록에는 결과와 출처, 계획 이탈, 실패·악화·누락 실행, 남은 설명, 후속 행동을 남긴다. 점수 순위와 별도로 무엇을 알게 되었고 다음 접근의 근거가 어떻게 달라졌는지 적는다. 새로 알아낸 것이 없으면 그 한계도 명시한다. 기전은 `확인 범위 / 잠정 설명 / 미확인`으로 구분하고 증거를 링크한다. 원인을 모를 때는 모른다고 쓴다.

미확인 목록은 세션 종료 시 검토하되, 목표 영향·정보 가치·비용에 따라 다음 RU를 고른다. 모든 의문을 자동으로 최우선 과제로 승격하지 않는다.

## 4. 측정과 판정

### 4.1 무엇의 불확실성을 측정하는지 먼저 정한다

1. **추정 대상:** 고정 데이터의 점수, 목표 모집단의 기대 성능, 재학습 평균, 지정 환경의 지연시간 중 무엇인가?
2. **변동 원천:** 데이터 표집, 초기화·학습, 환경·장치, 측정·수치 오차 중 무엇을 포함하는가?
3. **독립 단위:** 사용자·문서·사이트·실행 등 실질적으로 독립적인 단위는 무엇인가?
4. **비교 설계:** 대응·비대응, 반복 측정, 군집, 시간 의존성을 어떻게 처리하는가?
5. **판정 설계:** 효과 단위, 실용적 최소 효과, 구간 추정/검정 방법, 필요한 표본 수·정밀도는 무엇인가?

SD는 개별 관측의 산포, SE는 추정량의 변동성, CI는 가정과 설계에 따른 구간 추정이다. MDE는 지정한 오류율·검정력에서 검출하도록 설계한 효과 크기다. 실용적 최소 효과 `δ_min`은 목적과 비용으로 정한다. 이들을 하나의 “분해능 하한”으로 혼용하지 않는다.

### 4.2 실행 가능한 산출 절차

파일럿으로 변동 원천과 비교 차이의 산포를 조사하고 목표 정밀도 또는 검정력에 맞춰 본실험 규모를 정한다. 반복 세 번은 파일럿이 될 수 있지만 보편적 충분 조건은 아니다. 파일럿 결과를 후보 선택에 썼다면 그 선택 이력도 기록한다.

단순한 예로, 서로 독립인 `n`개 짝에서 후보와 기준선의 차이를 `d_i`라 하면:

- 평균 효과: `Δ̂ = mean(d_i)`
- 평균 차이의 표준오차: `SE(Δ̂) = s_d / √n`
- 차이가 정규분포라는 가정 아래 95% t 구간: `Δ̂ ± t_(0.975,n−1) × SE(Δ̂)`

여기서 `s_d`는 **차이의 표준편차**다. 정규성에서 크게 벗어나거나 군집·시계열 의존성이 있으면 설계에 맞는 다른 방법을 선택한다. 기준선의 SD만으로 비교 차이의 CI를 대신하지 않는다. [NIST: 대응 관측 분석](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm), [평균 신뢰구간](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm).

0과의 차이에 대한 양측 정규 근사 검정에서는 설계상 MDE를 대략 `(z_(1−α/2) + z_(1−β)) × SE_design`로 계획할 수 있다. 이는 해당 근사의 예시이며 작은 표본·다중 비교·군집 설계에는 그대로 쓰지 않는다. MDE는 관측 후 성공 컷오프가 아니며, `δ_min` 초과를 입증하려면 그 판정 목표에 맞춰 별도로 설계한다. [NIST: 유의수준·검정력과 표본 수](https://www.itl.nist.gov/div898/handbook/prc/section2/prc222.htm).

**결정론적 시스템:** 고정 데이터에서 같은 실행을 반복해 얻은 동일 점수는 새로운 독립 증거가 아니다. 새 표본에 일반화하려면 표본 불확실성을 평가한다. Bootstrap은 표집·의존 구조를 보존해야 하며 모든 불확실성을 자동으로 포착하지 않는다. 입력 섭동 실험은 지정한 섭동에 대한 강건성을 측정하며 표본 오차와 구분해 보고한다.

예상 효과를 현재 설계에서 구별하기 어렵다면 대응 설계·측정 개선·표본 확장·진단·보류를 비용과 함께 검토한다. 구조적 무라벨 지표는 후보 선별에 쓸 수 있지만 최종 목표에 대한 검증을 대신하지 않는다.

### 4.3 효과 없음과 판별 불가를 구분한다

효과 추정치와 불확실성, 실용적 기준을 함께 보고한다. 유의하지 않다는 사실만으로 무효과를 선언하지 않는다. [ASA 태스크포스 성명](https://magazine.amstat.org/blog/2021/08/01/task-force-statement-p-value/).

프로젝트는 주장에 맞는 판정 규칙을 사전에 고른다. 예를 들어 “효과가 `δ_min`보다 크다”는 주장에 대해 정한 구간이 전부 그 위면 지지, 전부 그 이하이면 그 크기의 효과를 반박, 경계를 걸치면 판별 불가로 정할 수 있다. 이는 가능한 규칙의 예시이며 유일한 통계 방법은 아니다.

동등성·비열등성은 별도의 허용 범위와 그에 맞는 분석을 사전에 정한다. 두 방법의 차이를 검출하지 못했다는 이유로 동등하다고 쓰지 않는다. 비용 감소를 목적으로 성능 비열등성을 평가하는 연구도 허용한다.

### 4.4 통제 비교와 귀속

**관심 효과를 식별할 수 있도록 비교를 설계한다.** 단순 디버깅에서는 한 번에 한 요인을 바꾸는 것이 유용하다. 여러 변경을 하나의 패키지로 비교하면 결론은 패키지 전체에 한정한다.

- 대응 비교·블록 설계·요인 설계를 허용한다. 요인 설계는 상호작용을 조사할 수 있다. [NIST: 단일 요인 변경 설계의 한계](https://www.itl.nist.gov/div898/handbook/pri/section2/pri212.htm).
- 같은 데이터나 시드를 공유했다는 이유만으로 비교군을 기각하지 않는다. 짝 내부 의존성과 짝 사이 독립성을 분석에 반영한다.
- 같은 생성원·배치·fold의 결과를 독립 반복으로 세기 전에 생성 및 표집 구조를 확인한다.
- 데이터, 전처리, 계산·탐색 예산, 실행 순서, 장치 조건의 차이를 기록하고 공정성 기준을 정한다.
- 작은 개별 효과가 판별되지 않았어도 최종 조합은 검증할 수 있다. 조합 성공은 개별 구성 요소의 효과를 입증하지 않는다. 반대로 개별 성공만으로 조합 성공을 보장하지 않는다.

### 4.5 사전 계획, 선택 편향, 일반화

확증 전에 주요 주장·지표·비교군·자료 범위·제외 규칙·표본 수 또는 중단 규칙·불확실성 분석·회귀 제약을 타임스탬프가 남는 계획으로 고정한다. 내부 계획 기록과 외부 등록을 구분하며, 외부 공개가 필요한지는 프로젝트에서 정한다. 탐색과 확증의 구분을 유지한다. [COS: 사전 등록](https://www.cos.io/initiatives/prereg-more-information).

후보·시드·시점·지표의 선택 이력과 실패한 실행을 기록한다. 확증에 여러 비교나 중간 확인이 포함되면 그에 맞는 다중 비교·순차 분석 등 유효한 설계를 사용한다. 같은 검증 자료에 반복해서 적응하면 선택 편향이 생길 수 있다. [Cawley & Talbot, 2010](https://www.jmlr.org/papers/volume11/cawley10a/cawley10a.pdf).

- 후보 선택용 자료와 최종 주장 평가용 자료를 구분한다. 최종 자료를 보고 수정하면 접근 이력과 역할 변경을 기록한다.
- 사후 기준 변경 시 원래 계획과 그 기준의 결과를 보존하고 변경 이유를 남긴다. 새 분석은 탐색적으로 표시한다. 새 확증에는 미사용 자료 또는 선택·적응을 반영한 유효한 설계가 필요하다.
- 단순 무작위 분할로 누수가 사라진다고 가정하지 않는다. 사용자·시간·사이트 중복, 전처리 학습 범위, 학습 자료와 평가 자료의 관계를 점검한다.
- 미사용 동일 분포 평가는 해당 목표 분포에 관한 증거다. OOD는 별도로 명시한 분포 이동 조건이다. OOD 주장이 있을 때 그 조건을 검증하며 모든 RU에 강제하지 않는다.
- 이미 전체 자료를 본 연구는 그 사실을 밝히고 탐색적·기술적 결론의 범위에 머물거나 새 평가를 설계한다.

### 4.6 계측과 구현의 값싼 오류를 먼저 점검한다

이상한 수치를 만나면 다음 점검을 우선하되 예산을 정한다. 모든 도구의 무결성을 완전히 증명할 때까지 가설 검토를 막지 않는다.

1. 조건·단위·분모·표본 수·누락 데이터·집계 방향을 확인한다.
2. 원시 출력과 집계를 대조하고 의도한 코드 경로가 실행되는지 확인한다.
3. 손으로 계산 가능한 작은 입력, 알려진 양성·음성 대조, 기준선을 사용한다.
4. 캐시·비동기 실행·워밍업·분산 집계 등 도구 특성을 점검한다.
5. 모델·가설과 계측 오류를 함께 후보 설명으로 비교한다.

출력 분산 0이나 상수 손실은 기대 동작과 비교해 해석한다. 표시 정밀도 때문에 0으로 보이는지 확인한다. 레이블 셔플 검사는 어디를 섞고 재학습하는지, 어떤 성능을 기대하는지 먼저 정한다. 기대와 다른 결과는 누수·검사 설계·표본 변동 등을 조사할 신호이며 단독 확정 증거가 아니다.

## 5. 연구 축의 종료·보류·재개

**현재 구성의 실패를 접근 전체의 불가능으로 확대하지 않는다.** 실험 결과와 자원 배분 결정을 구분한다.

| 필드 | 기록 내용 |
|:---|:---|
| `axis_id`, `status` | 축 식별자; 열림 / 반박됨 / 보류 / 판별 불가 |
| `claim_and_scope` | 평가한 주장과 적용 조건 |
| `evidence` | RU·결과 출처, 기전 근거 또는 미확인, 운영상 종료 사유 |
| `inside` | 동일 증거가 적용되는 재제안 범위 |
| `outside` | 비슷해 보여도 기존 결과가 적용되지 않는 조건 |
| `reopen_when` | 새 데이터·환경·예산·반박 증거 등 재검토 조건 |
| `decision` | 결정 주체·시점·권한 또는 관련 결정 레코드 |

기전 없이도 예산·우선순위 때문에 보류할 수 있다. 제한된 실험으로 가설을 반박했다면 그 조건을 명시한다. 보편적·영구적 불가능을 주장하려면 그 범위에 맞는 증명이 필요하다.

새 제안은 관련 축과 대조한다. 같은 전제와 증거 범위 안에서 이름만 바꾼 반복은 중단한다. 전제가 바뀌었다면 재개 조건 충족 여부를 조사하는 소규모 프로브를 기존 위임과 예산 안에서 수행할 수 있다. 승인 범위를 넘는 재개·고비용 실행은 §7에 따른다.

새 증거가 기존 결론과 충돌하면 자동 무시하지 않고 증거 품질과 적용 범위를 재검토한다. 세션 종료 시 새 기각·보류가 기록에서 빠지지 않았는지 확인한다.

## 6. 기록과 재현성

### 6.1 정본과 보고용 스냅샷

설정·현황·결과마다 관리 책임이 있는 정본을 정하고 링크한다. 수치를 보고서에 재인용할 때는 출처·버전·시점을 붙여 정본과 구분한다. 영향이 큰 설정·스키마 불일치는 필요한 자동 검사로 방지하되 모든 문장에 테스트를 만들지 않는다.

### 6.2 현황은 정정하고 증거는 보존한다

현황·설계 문서의 본문은 현재의 최선의 이해로 갱신한다. 확실한 사실, 잠정 설명, 미확인을 구분한다.

원시 결과·실행 로그·완료 RU·사전 계획·과거 결정은 결론을 바꾸기 위해 덮어쓰지 않는다. 오류는 원본을 보존한 정정 레코드로 표시하고, 현황 문서에서 잘못된 값을 계속 사용하지 않도록 수정한다.

### 6.3 결정 레코드

연구 방향·판정 기준·중요 구성·축 상태·규범의 변경에는 다음을 기록한다.

`id / 시점 / 맥락 / 결정 / 근거·출처 / 영향 범위 / 재검토 조건 / 결정 주체`

새 레코드에서 대체하는 이전 레코드의 ID를 참조한다. 과거 레코드 수정이나 상호 링크 추가를 강제하지 않는다. 재검토 조건이 당장 없으면 `현재 특정 조건 없음`으로 적되 영구 불변의 의미로 사용하지 않는다.

### 6.4 재실행에 필요한 최소 출처

결과 해석에 필요한 코드 커밋과 미커밋 변경, 설정·명령, 데이터 버전·분할, 환경·의존성, 관련 하드웨어, 시드·결정성 설정, 원시 산출물 위치를 기록한다. 비밀값 자체는 남기지 않는다. 대용량 데이터·가중치는 적절한 아티팩트 저장소와 버전 식별자로 참조한다.

### 6.5 과거 판단과 현재 정확성

과거 결정은 당시 정보와 규칙을 고려해 평가한다. 그러나 실제 오류나 유효하지 않은 분석이 발견되면 과거 결론도 정정한다. 그 결론에 의존하는 현행 구성은 영향도에 따라 재검증한다.

방향을 바꿀 때는 새 증거, 바꿀 이유, 기존 작업의 중단·보류 여부를 남긴다. 과거 경고와 반대되는 결정을 할 수 있지만 그 이유를 숨기지 않는다.

## 7. 에이전트의 실행과 보고

### 7.1 보고 무결성

- 측정한 주요·보조 지표의 변화와 알려진 회귀를 빠짐없이 추적한다. 요약에는 중요한 악화와 전체 결과 링크를 포함한다.
- 미실행·미측정·출처 미확인 항목을 `미검증`으로 표시한다. 관측, 추정, 해석을 구분한다.
- 실패·중단·누락 실행과 계획 이탈을 알린다. 일부만 완료했다면 완료 범위와 남은 일을 적는다.
- 테스트 통과를 연구 가설의 입증으로, 문서 작성을 실험 실행으로 보고하지 않는다.

### 7.2 위임과 판단 요청

기존 사용자 지시와 프로젝트의 위임·예산 범위를 먼저 확인한다. 그 안의 가역적인 구현·분석·진단·기준 초안 작성은 진행한다. 이미 승인된 동일 행동을 반복해서 승인받지 않는다.

다음이 기존 권한에 포함되지 않으면 판단을 요청한다: 핵심 목표 변경, 고정한 확증 기준 변경, 논쟁적인 축 재개, 예산 상한 초과, 외부 공개·공유, 되돌리기 어려운 작업. 구체적인 권한은 실제 도구와 실행 환경의 규칙을 따른다.

판단이 필요하면 **쟁점과 필요한 이유 → 근거가 있는 선택지 → 권고안과 필요한 승인 범위**를 간결하게 제시한다. 독립적으로 수행 가능한 허용 작업은 계속하고, 승인에 의존하는 작업은 기다린다.

### 7.3 범위와 효율

현재 질문이나 결과 신뢰성을 막는 문제는 해결한다. 그 외 발견은 기록하고 범위를 임의로 넓히지 않는다. 관련 없는 리팩터링·서식 변경을 섞지 않는다.

검색은 대상 경로와 파일 종류를 한정하고 로그는 필요한 부분을 추린다. 장시간 작업은 완료 알림을 우선 사용하며, 알림이 없으면 적절한 간격으로 상태를 확인한다. 바쁜 반복 확인을 피한다. 비밀키와 대용량 산출물을 일반 코드 이력에 넣지 않는다.

## 8. 실무 체크리스트

### 착수 전

- [ ] 해결할 문제·탐색할 가능성과 후보 범위를 택한 이유가 있는가? 점수 최대화만으로 연구 질문을 대신하지 않았는가?
- [ ] 질문·유형·증거의 용도와 예산이 명확한가?
- [ ] 탐색이면 범위·완료 기준을, 확증이면 주장·판정 규칙을 고정했는가?
- [ ] 추정 대상·독립 단위·비교 설계·변동 원천을 정했는가?
- [ ] 필요한 정밀도 또는 검정력과 실용적 기준을 구분했는가?
- [ ] 중단·판별 불가·실행 무효 처리와 관련 축 기록을 확인했는가?
- [ ] 자료 접근 이력과 코드·설정·데이터 출처를 남겼는가?

### 실행·해석 중

- [ ] 계측·구현의 값싼 오류와 비교 조건을 점검했는가?
- [ ] 짝·군집·fold·반복의 의존성을 반영했는가?
- [ ] 선택·중간 확인·사후 변경을 기록하고 분석에 반영했는가?
- [ ] 성능 관측과 기전 설명, 단회 관측과 재현을 구분했는가?
- [ ] 예산 상한과 위임 범위 안에서 수행하고 있는가?

### 종료 시

- [ ] 무엇을 배웠으며 그것이 다음 접근을 판단하는 데 어떤 근거가 되는가? 알아내지 못한 범위도 적었는가?
- [ ] 증거 판정과 운영 결정을 따로 적었는가?
- [ ] 실패·악화·누락 실행·미검증 및 계획 이탈을 보고했는가?
- [ ] 주장 범위와 기전의 확인 수준을 표시했는가?
- [ ] 축 상태와 재검토 조건, 필요한 결정 레코드를 갱신했는가?
- [ ] 현황은 정정하고 원시 증거·사전 계획은 보존했는가?
- [ ] 미확인 질문을 영향·비용에 따라 다음 후보로 정리했는가?

## 9. 부록 — ICF에서 얻은 동기와 일반화의 한계

아래는 [원안 §9](research_protocol.md)의 **보고를 요약한 것**이다. 원안은 450커밋·6주·78개 RU의 회고를 근거로 제시한다. v3 작성 과정에서는 저장소·원시 로그·통계 분석을 독립적으로 확인하지 않았으며 아래 수치는 **미검증 인용**이다.

| 제공 문서의 보고 | 유지할 교훈 | 이 사례만으로 결론낼 수 없는 것 |
|:---|:---|:---|
| 출력 분산 이상을 늦게 발견해 여러 버전을 소모 | 값싼 계측·구현 점검을 앞에 둔다. | 모든 상수 출력이 결함이라는 주장 |
| 진보를 만든 진단 6건 모두 계측·구현 문제와 관련 | 모델 변경 전에 측정 경로를 점검할 가치가 있다. | 모든 연구에서 계측 문제가 모델 문제보다 흔하다는 주장 |
| 비교 조건을 맞추자 겉보기 이득이 사라짐 | 비교 조건과 효과의 귀속을 확인한다. | 다요인 설계나 대응 비교의 무효 |
| 같은 축의 반복과 기각 기록 누락 | 적용 범위와 재개 조건을 남긴다. | 유사한 접근 전체의 영구적 불가능 |
| 채택 요소 6개의 효과가 당시 분해능 미만으로 보고됨 | 개별 기여를 확정하지 말고 최종 조합도 검증한다. | 각 효과가 모두 0이거나 전부 위양성이라는 주장 |
| 결정론적 구성으로 전환하며 판정 도구 재검토 필요 | 무엇의 불확실성을 재는지 다시 정의한다. | 결정론적 모델에 표본 추론을 사용할 수 없다는 주장 |
| 한계란 질문을 추적한 3일 동안 중요한 전환 | 미확인 질문을 실제 의사결정에 연결한다. | 프로토콜이 전환의 유일한 원인이라는 주장 |
| 정정 주석 누적으로 낡은 설명이 재전파 | 현황을 갱신하고 증거 이력과 분리한다. | 과거 기록을 삭제해야 한다는 주장 |

원안은 학습 성분을 결정론적 통계량으로 대체한 뒤 성능 대등·분산 43배 감소를 보고한다. 이는 진단에 기반한 변경의 사례로 참조할 수 있다. 다만 분산의 정의·표본 수·대등성 기준·비교 조건을 확인하기 전에는 통계적 동등성이나 보편적 효과로 재해석하지 않는다.

이 규범도 검토 대상이다. 적용 후에는 중복 실패 재발, 결론의 신뢰성, 재현 가능성, 정보 대비 비용, 문서 부담을 함께 살펴 수정한다. 규칙 준수율이나 실험 수 자체를 연구의 성공으로 삼지 않는다.
