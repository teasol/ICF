# CA-R1 — 쿼리 라벨 없는 과제 판별 신호 후보 제안서

> **작성:** 2026-09-08 · Idea Agent (엑셀) · **상태:** 제안 (채택·예산·판정은 Main의 몫)
> **표적:** `CA-R1`(Salience Anchor Subsampling, `REOPENED`이나 `활용 불가`) 및 §221 SHJ와 동일 구조의
> 교착 — 과제 특화 이득은 실재하나(§225 단조 용량반응 `|ρ| = 1.000`, ARID1A +2.97%p 대
> PBRM1 −6.64%p) 쿼리 라벨 없이 과제를 판별할 수단이 없어 활성화하지 못한다.
> 이미 기각된 신호 3종을 전제로 깔았다 — **A** 짝지은 context LOO(`CA-07`, ρ = −0.27 / −0.091),
> **B** draw 안정성 ICC(`CA-11`, 모든 강도에서 0.9996~1.0000으로 무판별), **C** 살리언스 집중도
> (§225 기각). 같은 신호를 형태만 바꿔 재제출하지 않도록 각 후보마다 A·B·C와의 관계를 명시했다.

### 후보 1: 슬라이드 단위 이상치 근접도 게이팅 (Per-Query Outlier-Proximity Gating)

**Task-Geometry와 다른 점:** Task-Geometry는 과제를 먼저 분류하고 그 결과를 과제 전체에 적용한다.
이 후보는 과제를 분류하지 않는다 — 판별을 애초에 "과제 단위"가 아니라 "쿼리 슬라이드 단위"로
내린다.

- **의심하는 전제**: A·B·C와 Task-Geometry를 포함해 지금까지의 모든 시도가 "선택 신호는 과제
  단위로 존재해야 한다"는 것을 암묵적으로 공유한다. 과제라는 범주 자체가 판별의 올바른 해상도가
  아닐 수 있다.
- **바꾸는 것**: 과제를 분류하는 대신, 각 **쿼리 슬라이드**가 context 임베딩 분포에서 얼마나
  이상치인지(예: whitened 좌표에서 context 최근접 k개까지의 평균 거리, 또는 `Percentile_98`
  지지집합 이탈도)를 슬라이드별로 측정해 그 슬라이드 개별로 salience subsampling 강도를 정한다.
  라벨은 context·query 어느 쪽도 쓰지 않는다(X만 사용).
- **반증 조건**: 슬라이드별 이상치 근접도와 그 슬라이드에 salience subsampling을 적용했을 때의
  실제 마진 변화(같은 fold 내 대응 비교, 판정 단계에서만 라벨 사용) 사이에 유의한 상관이 없으면
  기각한다. 특히 이상치 근접도가 슬라이드 크기(패치 수)의 대리변수에 불과하면(`|r|` 큼) 별도로
  기각한다.
- **기전**: 초점형(focal) 신호를 가진 양성 슬라이드는 context 정상 분포에서 이상치로 나타날
  것이라는 가설. **기전 미확인** — 이상치성과 salience subsampling의 이득 방향 사이의 인과 연결은
  검증된 바 없다.
- **닫힌 축 저촉**: `CA-11`과 형태가 비슷할 위험이 있다. 다만 CA-11이 닫은 것은 "여러 draw의
  앙상블 마진 간 **일치도**"이고, 이 후보가 재는 것은 "슬라이드 하나가 context 분포에서 얼마나
  **먼가**"로 대상과 연산이 다르다 — 같은 기각 기전(평균화 구조상 표본이 수백 개면 항상 수렴)에
  걸리는지는 실측해야 안다. `CA-07`과도 다르다 — LOO처럼 라벨로 예측 성능을 측정하지 않는다.
- **최소 구현 비용**: GPU 0. 저장된 32D 투영과 context 최근접 거리 계산뿐이며 1과제 50 fold 수 초.
  **이 후보가 GPU 0/단일 GPU 24시간 요건을 충족한다.**

### 후보 2: 컨텍스트 라벨 조건부 클래스 분리도 (Label-Conditioned Class-Mean Separation)

**Task-Geometry와 다른 점:** Task-Geometry는 라벨을 전혀 쓰지 않는다. 이 후보는 **컨텍스트** 라벨을
쓴다 — 닫힌 것은 "쿼리 라벨" 접근이지 "컨텍스트 라벨" 접근이 아니라는 점에 착안했다. 컨텍스트
라벨은 이미 Dual Ridge readout이 쓰고 있으므로 새로운 종류의 정보 접근이 아니다.

- **의심하는 전제**: 과제 판별 신호는 라벨을 일절 쓰지 않아야 한다는 전제(Task-Geometry가 이
  전제를 그대로 따른다). 실제로 막힌 것은 쿼리 라벨이며, 컨텍스트 라벨을 판독 이외의 **진단
  통계**로 쓰는 것까지 막혔다는 근거는 문서에 없다.
- **바꾸는 것**: 컨텍스트 라벨(y=0/1)만으로 두 클래스의 슬라이드 평균 임베딩 사이 거리와 클래스
  내/클래스 간 분산비(Fisher 판별비와 형태가 같으나 **기저를 회전하지 않고** 스칼라 진단으로만
  씀)를 과제 판별 특징으로 쓴다. 이는 `research_directions.md` §5(b)가 제안한 "SMAD4 클래스 간
  슬라이드 평균 분리도" 진단과 같은 계산을 과제 판별 용도로 재사용하는 것이다.
- **반증 조건**: 이 분리도 지표가 Primary 7 과제 간 통계적으로 유의한 군집을 이루지 못하거나
  (ANOVA `p ≥ 0.01`), 이 지표와 §225가 실측한 과제별 salience subsampling 최적 강도 사이에
  상관이 없으면 기각한다.
- **기전**: 초점형 병변은 클래스 평균이 가깝고 분산이 작은 소수 이상치 신호로 나타나는 반면
  거시형은 클래스 평균 자체가 크게 갈릴 것이라는 가설. **기전 미확인**.
- **닫힌 축 저촉**: `CA-06`(라벨 사용 판별 기저)에 형태가 걸린다 — 다만 CA-06이 닫은 것은
  "**기저(basis) 자체를** 라벨로 회전·선택"하는 것이고, 이 후보는 기저를 무감독 PCA로 그대로 두고
  그 위에서 스칼라 진단만 계산한다. CA-06의 경계 밖 조항("readout 단에서만 라벨을 쓰는 것")과
  구조가 같은지, 아니면 "기저 선택에 쓰지 않되 강도 선택이라는 별도 결정에 라벨 통계를 쓰는 것"이
  실질적으로 CA-06이 우려한 것(N≪D에서 라벨 방향이 노이즈를 오인)과 같은 실패 양식에 걸리는지는
  형태만 비슷할 수 있다 — 판정은 Main. `CA-07`과도 컨텍스트 라벨을 쓴다는 점에서 표면적으로
  닮았으나, CA-07은 **예측 성능**(LOO AUROC)을 신호로 쓴 것이고 이 후보는 예측을 전혀 하지 않고
  원시 거리·분산 통계만 쓴다.
- **최소 구현 비용**: GPU 0. 저장된 임베딩과 context 라벨만으로 1과제 50 fold 수 초.

### 후보 3: 과제 유추 최근접 이웃 매칭 (Task-Analogy k-NN in Fingerprint Space)

**Task-Geometry와 다른 점:** Task-Geometry는 고정된 파라메트릭 규칙(α, F 임계값으로 2분류)이다.
이 후보는 분류 규칙 자체를 두지 않는다 — Primary 7 각 과제의 알려진 최적 강도를 참조 라이브러리로
저장하고, 새 과제의 무감독 지문을 그 라이브러리와 **유사도로 보간**한다. 지문 성분으로 α·F를
재사용할 수도 있지만 핵심 차이는 선택 메커니즘(임계 분류 대 k-NN 보간)이다.

- **의심하는 전제**: 과제 판별은 소수(2~3개) 이산 범주로 깔끔하게 분리된다는 전제. Primary 7이
  단 7개뿐이므로 "거시형/국소형" 2분류가 실제 데이터를 얼마나 잘 대표하는지는 검증되지 않았다.
- **바꾸는 것**: Primary 7의 7개 과제 각각에 대해 무감독 기하 지문(공분산 스펙트럼 감쇠, 클래스
  분리도, 엔트로피 등 조합 가능)과 §225·본 문서 후보들이 실측한 최적 salience 강도를 짝지은 참조
  라이브러리를 만든다. 새 과제(SEAL의 미지 과제 포함)의 지문을 이 라이브러리와 비교해 최근접
  이웃 k개 과제의 강도를 거리 가중 평균으로 보간한다.
- **반증 조건**: Primary 7 leave-one-task-out 교차검증에서, k-NN 보간 강도가 전역 고정 강도(예:
  §225의 전체 평균 최적 강도)나 무작위 강도보다 유의하게 낫지 않으면 기각한다.
- **기전**: 기하학적으로 유사한 과제는 salience subsampling에 유사하게 반응한다는 국소 매끄러움
  가정. **기전 미확인** — 과제 7개로는 이웃 밀도가 극히 희박해 이 매끄러움 가정 자체가 통계적으로
  검증 불가능할 수 있다는 위험을 그대로 안고 제출한다.
- **닫힌 축 저촉**: 없음으로 판단하나, leave-one-task-out 절차가 "모델 선택은 Primary 7만으로
  수행한다"(`PROJECT.md` §3.1)는 규칙과 어떻게 상호작용하는지(참조 라이브러리 구축 자체가 이미
  Primary 7 성능 정보를 쓰는 셈이라 선택 편향 경로가 되는지)는 확인이 필요하다 — 저촉 여부는
  Main 판정.
- **최소 구현 비용**: GPU 0에 가까움. 지문 계산은 저장된 통계 재사용, k-NN 자체는 7×7 거리
  행렬 수준이라 사실상 즉시. leave-one-task-out 검증까지 포함해도 350-fold 스윕 결과를 재활용하면
  추가 GPU 비용은 거의 없다.

### 후보 4: 컨텍스트-쿼리 분포 불일치량을 직접 신호로 사용 (Context-Query Distributional Shift as Signal)

**Task-Geometry와 다른 점:** Task-Geometry는 context 내부의 형태(스펙트럼)만 본다. 이 후보는
context와 query **두 분포 사이의 관계**를 잰다 — §221이 지목한 "context↔query 분포 이동"을
간접 성능 신호(LOO)가 아니라 순수 기하 거리로 직접 측정한다.

- **의심하는 전제**: 지금까지의 실패(A: context LOO)는 "context 내부에서 관측된 **예측 성능**은
  query로 전이되지 않는다"는 것을 보였을 뿐인데, 이것이 "context-query **분포 불일치의 크기**도
  신호가 될 수 없다"로 암묵 확대되어 있었다.
- **바꾸는 것**: 라벨을 전혀 쓰지 않고, context 임베딩 분포와 query 임베딩 분포 사이의 MMD(또는
  Wasserstein 거리)를 fold마다 계산한다. 이 값이 클수록 salience subsampling 강도를 낮추는 규칙을
  세운다.
- **반증 조건**: MMD 값과 salience subsampling으로 인한 fold별 성능 변화(같은 fold 대응 비교,
  판정 단계에서만 라벨 사용) 사이에 유의한 상관이 없으면 기각한다.
- **기전**: 분포 이동이 클수록 context에서 정의한 살리언스 앵커가 query에 부정확하게 일반화된다는
  가설. `CA-07`의 재개 조건 문구("context↔query 분포 이동을 직접 교정하는 수단이 확립되는 경우")와
  정확히 같은 문제를 겨냥한다. **기전 미확인**.
- **닫힌 축 저촉**: `CA-07`의 재개 조건 자체를 겨냥하는 후보이므로 형식적으로는 **CA-07을 다시
  여는 시도**에 가깝다. 다만 CA-07이 닫은 것은 "LOO **점수**를 선택 신호로 쓰는 것"이고 이 후보는
  예측이 아니라 원시 분포 거리를 쓰므로 같은 저촉인지, 다른 접근인지는 형태만 비슷할 수 있다.
  `CA-13`(외부 retrieval)과는 무관 — context·query 모두 에피소드 내부 데이터다.
- **최소 구현 비용**: GPU 0~단일 GPU. MMD는 저장된 임베딩 위에서 커널 계산만 필요하며 1과제
  50 fold 기준 수 분 이내로 예상(미검증).

### 후보 5: 다중 강도 DS를 외부 선택 없이 동시 앙상블 브랜치로 투입 (Multi-Intensity DS as Simultaneous Branches, No External Selector)

**Task-Geometry와 다른 점:** Task-Geometry를 포함한 나머지 5건은 전부 "먼저 과제(또는 슬라이드)를
판별한 뒤 강도를 조회/보간한다"는 2단계 구조를 공유한다. 이 후보는 그 2단계 구조 자체를 버린다 —
판별을 아예 하지 않는다.

- **의심하는 전제**: `CA-R1`이 전제하는 것은 "과제별 최적 강도를 앙상블 밖에서 먼저 선택해야
  한다"는 것, 즉 선택이 readout(Dual Ridge) **이전에** 일어나야 한다는 전제다.
- **바꾸는 것**: §225의 DS 강도 스윕이 이미 만든 여섯 강도(`m_ds_full, f070, f050, f030, f010,
  f000`)를 택일하지 않고 **여섯 개의 별도 브랜치로 동시에** 앙상블에 편입한다. 과제별 최적 강도
  선택은 외부 신호가 아니라, 매 fold마다 context 라벨로 다시 적합되는 Dual Ridge 계수 자체가
  수행한다 — 각 강도 브랜치의 계수가 과제마다 context 적합도에 따라 자동으로 커지거나 작아진다는
  것이 기대다.
- **반증 조건**: 6개 강도 브랜치 간 상관이 매우 높아(예: 서로 `|r| > 0.9`, 기존 단일 DS와도
  `|r| > 0.9`) 게이트 ① 유효 랭크가 오히려 하락하면, 또는 승격 판정(대응 Δ의 과제 군집 구간)에서
  이득이 없으면 기각한다.
- **기전**: Ridge 회귀가 다중공선적 예측변수 중 라벨과 더 잘 정렬된 변수에 자연스럽게 큰 계수를
  배정한다는 표준 통계 성질. 이 원리 자체는 일반적으로 알려져 있으나, **이 구체적 브랜치 구성·이
  fold 규모(`N_ctx` 90~261)에서 실제로 그렇게 작동하는지는 `기전 미확인`**이다.
- **닫힌 축 저촉**: `P2-SELECTOR-CEILING`(§224 Oracle 금지, `research_directions.md` §4.1)과
  표면 형태가 비슷해 보일 위험이 있다 — 둘 다 "여러 강도 중 사실상 최선을 고른다"는 결과를 낳을 수
  있어서다. 그러나 이 후보는 **라벨을 미리 보고 최댓값을 고르는 것이 아니라**, 이미 프로젝트가
  승인한 readout 메커니즘(Dual Ridge, context 라벨만 사용해 fold별로 닫힌 형태로 계수를 푸는 것)을
  그대로 재사용하는 것이라 Oracle과 같은 기전인지는 실행해 봐야 판별된다. `CA-09`(평균의 새로운
  사영·재가중 브랜치)에도 걸릴 수 있다 — DS 자체가 이미 위치 계열의 살리언스 재가중이므로 그
  변형을 다중화하는 것이 "위치 계열을 다시 사영·재가중해 새 브랜치를 만드는 것"에 해당하는지는
  판단이 갈릴 수 있다. `CA-14`(학습 파라미터 기반 readout)는 저촉하지 않는다 — Dual Ridge는
  경사하강이 아니라 닫힌 형태 해다.
- **최소 구현 비용**: 350-fold 스윕 1회, 단일 GPU 24시간 이내로 충분(기준 단가 0.7~1.0 GPU-h
  수준에 강도 5개 추가 브랜치의 소폭 오버헤드, 미검증). **이 후보도 GPU 0/단일 GPU 24시간 요건을
  충족한다.**

### 후보 6: 외부 대규모 병리 코호트에서 사전학습한 Task-Type 메타분류기 (Externally Pretrained Meta-Classifier)

**Task-Geometry와 다른 점:** Task-Geometry는 Primary 7의 7개 샘플만으로 규칙을 세운다. 이 후보는
그 표본 크기 자체가 병목이라고 본다 — PathoBench 밖의 외부 데이터로 판별 규칙을 사전학습한 뒤
고정된 함수로만 반입한다.

- **의심하는 전제**: 과제 유형 판별 신호는 현재 Primary 7의 7개 과제만으로 구축해야 한다는 전제.
  Task-Geometry를 포함한 모든 기존·본 문서의 시도가 여기 갇혀 있다 — 과제가 7개뿐이라 어떤
  임계값·회귀도 통계력이 사실상 없다.
- **바꾸는 것**: TCGA/CPTAC 등 PathoBench 밖의 대규모 외부 병리 과제 수십~수백 개(각각 알려진
  "국소형/거시형" 유형)를 모아, 그 과제들의 context 분포 기하 지표(공분산 스펙트럼, 클래스 분리도
  등)와 실제 유형 사이의 관계를 회귀·분류기로 사전학습한다. 학습된 것은 in-context 판독 경로
  안으로 들어가지 않고, 새 에피소드의 강도를 조회하는 **고정된 룩업 함수** 역할만 한다.
- **반증 조건**: 메타분류기가 Primary 7 leave-one-out에서 무작위 수준(50%) 판별력만 보이면
  기각한다. 외부 코호트의 "국소형/거시형" 라벨링 기준 자체가 병리학적으로 불명확하면(구성 타당도
  문제) 착수 이전에 기각한다.
- **기전**: 국소 병변형/거시 조직형 구분이 여러 병리 과제에 걸쳐 공유되는 보편적 기하학적 서명을
  가진다는 가설. **기전 미확인** — 이 구분이 병리학적으로 이산 범주인지 연속 스펙트럼인지도
  불명확하다.
- **닫힌 축 저촉**: `CA-14`(학습 파라미터 기반 readout/head)와 `CA-13`(외부 retrieval 계층) 양쪽에
  형태가 걸린다. CA-14는 "경사하강으로 학습되는 파라미터를 **활성 경로**에 되돌리는 것"을 닫았는데,
  이 메타분류기는 in-context margin 계산 경로에는 파라미터를 넣지 않고 강도 "선택"만 담당하므로
  CA-14가 말하는 "활성 경로"에 해당하는지가 관건이다. CA-13은 "에피소드 밖 외부 풀에서 이웃을
  검색해 context를 보강"하는 것을 닫았는데, 이 후보는 context를 검색으로 보강하지 않고 외부
  데이터로 **사전학습된 고정 함수**만 반입하므로 검색(retrieval)과 다르지만, CA-13의 재개
  조건("후보 풀이 현재보다 훨씬 큰 경우")과는 오히려 부합하는 모양이다. 두 축 모두 표면적 저촉이지만
  실제로 그 기각 기전(학습 불안정성·일반화 실패, retrieval 무이득)에 걸리는지는 다를 수 있다 —
  프로젝트 정체성(`PROJECT.md` §1, "학습 파라미터 0개의 결정론적 in-context 분류기")과의 충돌
  여부까지 포함해 판정은 Main.
- **최소 구현 비용**: **가장 비용이 크고 불확실한 후보다.** 외부 대규모 코호트 확보·유형
  라벨링·기하 지표 추출·메타분류기 학습 전체가 필요해, 최소 구현조차 현재 GPU-h 단위 예산
  스케일을 벗어날 수 있다. 데이터 접근성에 의존하므로 최소 구현 비용 자체가 `미확인`이다. 비용이나
  실현 가능성을 이유로 후보를 내리지 않고 그대로 제출한다.

## 추천 (결정 아님)

**가장 판별력이 높다고 보는 것은 후보 5(다중 강도 DS 동시 편입)다.** 나머지 5건은 전부 "과제(혹은
슬라이드)를 무언가로 분류·매칭한 뒤 조회한다"는 구조를 공유하며, 그 구조 자체가 이미 두 번
(§212·§221) 실패한 "context 내부 신호 → query 전이" 문제를 다른 형태로 반복할 위험을 안고
있다. 후보 5는 그 구조를 우회해 이미 검증된 readout 메커니즘(Dual Ridge)에 선택을 맡기므로,
실패하더라도 "판별 신호가 없다"는 것과 별개로 "readout에 정보를 넘기는 것만으로는 부족하다"는
더 강한 사실을 알려준다. 다만 이는 추천이지 결정이 아니며, Oracle 금지 조항과의 경계(§224)를
Main이 먼저 판정해야 착수 여부가 정해진다.
