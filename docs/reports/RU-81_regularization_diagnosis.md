# RU-81 — Ridge 정규화 진단 종료 보고

2026-09-07 · 유형 `diagnostic` · 실행 `ru81_reg_20260907_r1` · **hold-out 미검증**

## 1. 결론과 운영 결정

**같은 λ=1이 브랜치마다 같은 수축을 뜻하지 않는다는 관측은 지지된다. 정규화 변화는 예측 순위와 마진 크기를 모두 바꾸지만, 앙상블의 일관된 성능 개선은 판별 불가다.**

수축 차이 자체는 결함이나 과적합의 입증이 아니다. 서로 다른 특징에 같은 수축률이 최적이라는 근거도 없다. 12개 비교 전부 과제 군집 95% 구간이 0을 포함한다. 이를 무효과·동등성·정규화 축의 불가능으로 해석하지 않는다.

**운영 결정:** 기준선을 유지하고 이 3점 진단을 종료한다. 특정 λ 처방과 승격은 보류한다. 정규화 연구 축은 닫지 않는다. 다음 후보는 저장 마진을 이용한 순위 변화와 크기 변화의 분리 진단이며, 별도 RU·예산으로 확정한다. 결정은 `D-024`.

## 2. 무엇을 알았는가

`df/rank`는 저장 Gram 고유값 e에 대한 Σ e/(e+λ)를 수치 rank로 나눈 진단량이다. 아래는 350 folds의 평균이며, 정확도·신뢰도·최적 정규화 강도의 척도가 아니다.

| 브랜치 | Gram 규모 평균 | λ=1의 df/rank |
|---|---:|---:|
| CV | 347.893 | 0.982 |
| BM | 1.960 | 0.493 |
| QA | 2.347 | 0.294 |
| DS | 1.984 | 0.464 |

- **CV는 기준 λ에서 수축이 약하다.** 다른 세 브랜치와 정규화의 상대적 강도가 다르다는 출발 관측을 확인했다. 브랜치 차원·표준화·스펙트럼을 분리 개입한 실험은 아니므로 차이의 원인을 하나로 확정하지 않는다.
- **H1 — 순위와 앙상블의 동반 반응:** 순위 민감도는 관측됐다. 예를 들어 CV의 중간 강도에서 단독 Δ는 +1.1972%p·5/7이나 앙상블 Δ는 +0.1304%p·3/7, 구간 [-0.2489, +0.5096]%p다. 단독 악화는 KEAP1·SMAD4, 앙상블 악화는 ARID1A·KEAP1·SMAD4·Progression이다. 일관된 앙상블 개선이나 정규화 처방의 유효성은 입증되지 않았다.
- **H2 — 마진 크기와 결합의 영향:** 추가 진단 가치가 있다. BM 강한 수축에서 단독 Δ -0.7216%p·2/7과 앙상블 Δ +0.1569%p·4/7의 방향이 달랐다. 그러나 순위도 바뀌었으므로 이를 순수한 마진 크기 효과로 귀속하지 않는다. 단독 악화는 KEAP1·KRAS·SMAD4·Progression·PBRM1, 앙상블 악화는 Grade·KEAP1·PBRM1이다.
- **H3 — 전반적인 출력 둔감성:** 이 범위의 일반적 설명으로는 관측과 맞지 않는다. 강한 수축에서는 순위 상관과 마진 RMS가 함께 변했다. 다만 앙상블 평균 효과의 구간이 넓으므로 “출력 변화가 없다”와 “평균 개선이 불확실하다”를 구분한다.
- H1/H2/H3의 정량 분류 경계는 사전 카드에 없었다. 사후 cutoff로 승자를 정하지 않고 각 설명의 지지 범위와 한계를 기술한다. **순위·크기·상보성 중 무엇이 앙상블 변화를 주도하는지는 기전 미확인**이다.

## 4. 실행 유효성·독립 검산

- 7과제 × 50 official folds, 총 350 folds와 14 shards가 모두 완료됐다. GPU 0~7 사용, wall 680.58초, worker wall 합산 1.2934 GPU-h(상한 2h 이내). GPU 사용량은 GPU 연산기 실제 점유율 적분이 아닌 프로세스 경과시간 합계다.
- 기준 λ solver replay와 원래 브랜치 경로 대비 최대 마진 오차는 각각 0. 독립 float32 집계와 원래 확률의 최대 오차는 1.7882e-7로 사전 허용치 이내다. 프로브의 비유한 출력 없음, merged baseline·probe의 fold/slide ID/label 대응 일치.
- 독립 검산은 기존 report의 metric·ensemble 함수를 import하지 않고 원시 마진으로 다시 계산했다. 모든 양성/음성 쌍의 비교와 tie=0.5 방식으로 AUROC를 검산했다. Δ·과제 평균·구간 최대 차이는 3.47e-18, 순위 상관 최대 차이는 2.22e-16이다.
- 실행 manifest의 4개 진단 코드 파일·실행 전 카드와 7개 공식 fold 파일의 SHA256을 종료 기록 수정 전에 확인했다. 결과 원문을 덮어쓰지 않고 audit.json을 별도로 추가했다.
- 단독 AUROC는 마진 순위로, 앙상블은 sigmoid 후 Trimmed Mean으로 계산했다. bf16-mixed 특징 경로는 유지했으며 이 실행이 fp32 민감도 문제까지 해결한 것은 아니다.
- 개입 λ는 Context geometry에서만 결정했다. 과제당 양쪽 shard에 동일 공식 fold를 분담했으며 새 분할·hold-out 접근은 없다. 전체 평가 파이프라인의 누수 부재를 이 replay만으로 완전히 증명한 것은 아니다.

## 5. 계획 이탈·실패·남은 한계

- 첫 시작 `ru81_reg_20260907`은 선택적 체크포인트 탐색과 shell errexit 충돌로 rc=2 종료했다. GPU 평가·성능 조회 전 실패였고 수정 후 새 태그 r1로 완주했다. 디버그 시작도 같은 초기 오류만 확인했다.
- 5시간 도구 사용 한도로 구현·검증 후 중단됐다가 다음 날 재개했다. 활동 작업시간은 별도 자동계측하지 않아 카드의 구현 2시간 상한 준수는 확인 불가다. GPU 시간 상한은 manifest로 확인했다.
- 이미 Primary 7의 과거 결과와 이번 12개 비교를 열람했다. 재사용한 자료로 후보를 고른 뒤 같은 결과를 새 확증으로 부르지 않는다. CI가 0을 포함한다는 사실은 효과 없음이나 실용적 동등성의 입증이 아니다.
- 확인한 것은 기존 특징 위 정규화의 3점 반응이다. λ 연속 구간 전체, 브랜치 조합 변경, 신규 특징, 학습 자료 확대, hold-out 일반화는 미검증이다.
