# 전체 리팩터링 — 로컬 모델에 위임하고 검증한 기록

사용자 지시로 코드 리팩터링과 문서 정리를 로컬 모델(`deepseek-v4.1-flash`, opencode)에
위임했다. 이 문서는 **무엇을 맡겼고, 무엇을 믿었고, 무엇을 직접 확인했는지**를 남긴다.

## 왜 한 덩어리로 맡기지 않았는가

이 저장소는 연구 코드이고, 2026-09-18 하루가 통째로 계측 무결성 문제였다. 리팩터가 수치를
1비트라도 바꾸면 저장소의 모든 비교가 무효가 된다. 그래서 여섯 작업 중 **넷은 편집 권한이
없는 조사 작업**으로 만들었다.

삭제·통합은 **연구 의도에 대한 판단**이다. 지금 호출되지 않는 스크립트가 과거 실행 재현에
필요할 수 있으므로, 배경 편집이 내릴 결정이 아니다.

각 작업은 별도 git worktree의 별도 브랜치에서 돌았다. 회차와 실험이 main을 읽는 중에 그
아래를 고치면 진행 중인 회차가 깨진다.

## 보고를 그대로 믿지 않았다 — 세 건을 직접 확인했다

### 1. "`trimmed_mean` 6개 구현, 확률 vs 마진 입력 차이가 가장 위험" — 절반만 맞다

입력 차이는 **무해하다.** 분석 사본은 확률을, 정본은 로짓을 반환하는데 AUROC는 단조 변환에
불변이다.

**진짜 결함은 가드 부재였다.** `eval_gated_voting`과 `ru82_lambda_ensemble`에 `len < 3`
가드가 없어 멤버가 2개면 빈 슬라이스를 평균해 조용히 `NaN`이 된다. 다만 두 호출부 모두
항상 5개를 넘기므로(`branches` 5개, `ALL_BRANCHES` 5개) **과거 결과는 영향받지 않았다.**
함정을 막은 것이지 틀린 수치를 고친 것이 아니다.

확인하는 김에 잰 값: 가드 있는 사본과 정본의 차이는 최대 `1.19e-07`로, 방법 차이가 아니라
부동소수 연산 순서다.

### 2. "CI 하한이 `-0.0114`와 `-0.0115`로 어긋난다" — 둘 다 맞다

같은 통계량이지만 입력이 다르다. 실행 로그의 반올림된 fold-mean으로는 `-0.01148`,
예측 파일에서 fold 단위로 재계산하면 `-0.01151`이다. 재계산 쪽으로 통일하고 이유를 적었다.

### 3. `config.py`에서 `Sequence` import 제거 — 위험했으나 안전했다

그 파일은 `get_type_hints`를 쓴다. 타입 주석이 문자열이면 런타임에 모듈 네임스페이스에 그
이름이 있어야 하고, **`py_compile`은 이것을 잡지 못한다.** 실행해서 확인했다 — 101개 필드가
해석되고 YAML 파싱도 통과한다. 실제로 미사용이었다.

`training_free.py`에서 빠진 별칭 import 6개도 전 저장소를 뒤져 참조가 없음을 확인했다.
`common/__init__.py`는 `solvers.py`에서 직접 가져간다.
