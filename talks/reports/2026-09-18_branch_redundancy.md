# 유효 랭크 `3.52 / 7` — 처음으로 실제 Primary 7 margin에서 재확인

여러 회차가 "유효 랭크 `3.52`가 branch 추가의 포화를 뜻하는가"를 물었고, 답할 수 없었다.
**집계된 확률만 분류기 밖으로 나왔기 때문이다.** `branch_margins()`가 그걸 열었고, 이것이
그 첫 측정이다.

## 방법

공식 7-branch 설정, Primary 7, 과제당 fold 50. 각 fold에서 query slide에 대한 branch별
margin을 받아 **fold 안에서 표준화한 뒤** 모으고 상관행렬을 만든다. 표준화가 없으면 fold 간
스케일 차이가 branch 일치로 둔갑한다.

**라벨은 한 번도 쓰지 않는다.** 게이트 ① 성격의 진단이므로 이 출력은 승격 근거가 될 수 없다.

## 결과 — 문서 수치가 재현된다

| 과제 | eff.rank (참여비) |
|:---|---:|
| `cptac_lscc/ARID1A_mutation` | `3.483` |
| `cptac_lscc/Histologic_Grade` | `3.511` |
| `cptac_lscc/KEAP1_mutation` | `3.578` |
| `cptac_luad/KRAS_mutation` | `3.314` |
| `cptac_pda/SMAD4_mutation` | `3.739` |
| `ucla_lung/progression_regression` | `3.001` |
| `cptac_ccrcc/PBRM1_mutation` | `3.999` |
| **평균** | **`3.518`** |

`PROJECT.md` §의 `3.52 / 7`과 **소수 둘째 자리까지 맞는다.** `BM`·`QA`·`DS` 부분 집합도
문서의 `1.29 / 3`에 대해 측정 `1.29`(범위 `1.23`\~`1.47`)로 맞는다.

앵커 수치들이 재현되지 않던 것과 달리, 이 둘은 재현된다.

### 정의를 먼저 맞춰야 했다

처음에 **엔트로피 정의**(`exp(-Σ p log p)`)로 재고 `4.61`을 얻어 "문서 수치가 재현되지
않는다"고 판단했다. **틀렸다.** 문서의 `3.52`는 `branch_diagnostics.py`가 쓰는 **참여비**
(`(Σλ)² / Σλ²`)이고, 같은 행렬에 두 정의를 적용하면 `4.61`과 `3.52`가 나온다.

같은 이름의 지표가 두 정의를 갖고 있었고, 그 차이가 "재현 실패"로 보일 뻔했다. 스크립트는
이제 **참여비를 주 값으로** 내고 엔트로피 값을 `entropy_rank`로 따로 기록한다.

## 중복은 흩어져 있지 않고 한 계열에 몰려 있다

**7개 과제 전부에서 최상위 상관 쌍이 `BM`-`QA`다**(`0.897`\~`0.931`).

| branch | 타 branch 대비 평균 `|r|` |
|:---|---:|
| `BM` | `0.459` |
| `QA` | `0.454` |
| `DS` | `0.413` |
| `CV` | `0.360` |
| `SH` | `0.231` |
| `SJ` | `0.078` |
| `BD` | `0.062` |

`BM`·`QA`·`DS`는 셋 다 **PCA-32에 투영한 bag-mean 계열 readout**이고, 참여비 `1.29 / 3`은
사실상 하나의 신호다. 반면 `BD`(스펙트럼 엔트로피)와 `SJ`는 나머지와 거의 독립이다.

**따라서 `3.52`는 "branch 추가가 포화됐다"는 뜻이 아니다.** 7개 중 3개가 같은 것을 재고
있다는 뜻이다. 회차들이 물었던 두 해석 중 **"서로 다른 것을 재는 branch를 아직 못 만들었다"**
쪽에 증거가 실린다. 다만 이것은 **현 7개의 구조**에 대한 관측이지, 새 branch가 실제로 성능을
올린다는 근거는 아니다.

## 게이트 ①의 "내부 모순" — 철회한다

처음에 이렇게 적었다: 게이트 ①이 `max |r| > 0.6`을 기각하는데 공식 구성 안의 `BM`-`QA`가
`0.90`\~`0.93`이므로 **현 구성은 자기 게이트를 통과하지 못한다**고.

**틀렸다.** 회차 `C-20260918-23`이 정정했다. `PROJECT.md` §5는 게이트 ①을 **신규 브랜치
채택 게이트**로 정의하고 기준 집합을 공식 7-branch로 못박는다. 검사 대상은 **후보와 기준
집합 사이의 쌍**이지 기준 집합 **내부** 쌍이 아니다. 따라서 `BM`-`QA` `0.90`은 게이트 위반이
아니고, 게이트가 기존 구성을 기각한 적도 없다. 모순은 문서에 있지 않고 내 독해에 있었다.

남는 물음은 따로 있다. 기준 집합 내부에 `0.90`짜리 쌍이 있는데 후보에게는 `0.6`을 요구하는
것이 **의도된 비대칭인가.** 신규 후보에게만 기존 브랜치보다 엄격한 기준을 적용하는 이중잣대
문제는 `PROJECT.md` §5.1이 게이트 ②에 대해 이미 지적하고 해소한 적이 있다. 게이트 ①에도
같은 물음이 성립하는지는 **판별 불가**로 둔다 — 그 비대칭이 의도인지 누락인지는 기록에 없다.

## 탐색적 관측 (확증 아님)

과제별 `SJ` 중복도와 parity의 7-5 Δ 사이 상관이 **`+0.648`**이다(`n=7`). 부호는 직관과
반대다 — `SJ`가 기존 branch와 **더** 겹치는 과제에서 7-branch가 **더** 이득을 본다.

**이 상관은 확증이 아니다.** (1) `n=7`이고, (2) parity Δ를 **먼저 본 뒤에** 계산했다.
사후에 고른 관계이므로 선택 편향이 있으며, 이 프로젝트가 §214에서 경고한 구조다.
가설 생성용으로만 기록한다. 검증하려면 이 관계를 **사전 선언하고** 다른 과제 집합에서
재야 한다.

## 한계

- 상관은 **query slide의 margin** 위에서 쟀다. context slide나 fold별 상관을 평균하는
  방식과는 다를 수 있다. 문서의 `3.52`가 어느 방식이었는지는 기록에 없다 — 값이 맞는 것이
  방법이 같다는 증거는 아니다.
- fold 안에서 표준화했으므로 **fold 간 스케일 정보는 버려졌다.** 그 정보가 중요한 축이라면
  이 측정은 그 부분을 보지 못한다.
- `hold-out 미검증`이며 `SEAL 10`은 보지 않았다(`D-047`).
