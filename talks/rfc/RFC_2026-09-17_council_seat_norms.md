# RFC: 다자 토론(협의체)에 맞춘 좌석 기반 에이전트 규범 재편

- **Status**: Approved
- **Date**: 2026-09-17
- **Author**: Claude Code (소집자 겸 종결권자, 사용자 지시에 의한 겸임)
- **Target Module**: `AGENTS.md`, `docs/agent_handoff.md`, `scripts/call_agent.sh`, `talks/rfc/RFC_TEMPLATE.md`
- **결정 레코드**: `D-046`

> **템플릿 준수에 관한 참고**: `RFC_TEMPLATE.md`는 섹션 소유자를 `Orca`/`Owl`/`Lime`으로
> 고정하고 있으나, 그 고정 배속 자체가 이 RFC의 개정 대상입니다. 따라서 템플릿의 섹션
> 소유자 표기를 따르지 않고 사안 중심으로 기술합니다. 이 RFC는 사용자 결정으로 확정되었으며,
> `Owl`·`Lime` 세션의 독립 검토를 거치지 않았습니다. **이는 다자 검토가 아닙니다.**

---

## 1. 문제 정의

사용자 지시: 다수의 서브 에이전트가 **토론을 통해 더 나은 아이디어를 내는** 운영 방식을
도입하되, 현행 에이전트 문서가 그 방식과 맞지 않으므로 규범부터 확정한다.

개정 이전 `AGENTS.md`(2026-09-10 판)를 다자 토론 기준으로 점검한 결과, 어긋나는 지점 일곱 가지를
확인했습니다. 아래는 문서 조문에 대한 대조이며, 운영 실패의 실측 보고가 아닙니다.

1. **역할이 영속 세션과 1:1로 고정**되어 있습니다. `Orca`/`Owl`/`Lime`은 각각
   `scripts/call_agent.sh`의 고정 session ID 하나에 묶여 있어, 같은 관점의 좌석을 N개
   병렬로 두는 개념이 없습니다. 영속 세션을 resume하는 호출 구조에서 병렬 소집은 문맥이
   직렬화되고 교차 오염됩니다.
2. **§2-2가 구조 자체를 금지**합니다. "한 세션에서 역할 이름만 바꿔 여러 전문가가 참여한
   것처럼 쓰지 않는다"는 조문은 **동일 모델 위에 system prompt로만 좌석을 나누는** 협의체
   구조와 정면으로 충돌합니다. 조문의 의도(가짜 다자성 금지)는 타당하므로 폐기하지 않고,
   판별 기준을 "세션이 다른가"에서 "**정보가 격리되었고 반증 의무를 지는 좌석이 있는가**"로
   옮겼습니다.
3. **앵커링·합의 오염에 대한 규정이 없습니다.** §2-7이 "동의는 검증이 아니다"까지만 말하고,
   누가 누구의 출력을 언제 보는지에 대한 순서·격리 규정이 전혀 없었습니다.
4. **종합·종결 주체가 정의되지 않았습니다.** 현행은 Reasoning 단독 판정 구조여서, 종합
   좌석의 산출물이 판정인지 재료인지 구분되지 않습니다.
5. **§4 서명 규칙이 좌석을 표현하지 못합니다.** 좌석 다수가 같은 모델일 때 무엇을 작성자로
   적을지 규정이 없었습니다.
6. **예산 규정이 1회 호출 기준**이라, 좌석 수 × 단계 수로 비용이 곱해지는 구조의 상한과
   중단 조건이 없습니다.
7. **로컬 모델 산출물의 지위가 미정의**입니다.

## 2. 확정한 개정 (사용자 결정 3건)

| 쟁점 | 선택 | 내용 |
|---|---|---|
| 구조 관계 | **좌석 중심 재편** | 고정 5역할을 폐지하고 좌석(전이적)과 직(지속) 2층으로 재편 |
| 산출물 권한 | **저위험은 협의체 종결** | `T0` 화이트리스트 한정, 4개 조건 동시 충족 시 |
| 좌석 구성 | **질문마다 동적 편성** | 최소 구성과 사전 기록 의무로 편향을 통제 |

### 2.1 좌석과 직

- **좌석(seat)**: 한 회차의 한 검토 관점. 회차 종료 시 소멸. 유형 `P`(제안) `R`(반증)
  `A`(감사) `G`(일반화) `T`(이론) `M`(실측) `S`(종합).
- **직(office)**: 소집자 / 종결권자 / 기록자 셋만 지속. Idea·Coding은 직에서 내려와
  각각 `P` 좌석과 `M` 좌석으로 흡수했습니다.
- 최소 구성 `P`+`R`+`S`. **`R` 좌석이 없는 회차는 무효**, **`S`는 `P`와 같은 문맥일 수 없음**.

### 2.2 동적 편성의 위험과 대응

동적 편성의 주된 위험은 **소집자의 편향이 좌석 구성에 그대로 반영되는 것**이며, 회차 간
비교도 어려워집니다. 대응은 **결과를 보기 전 편성 근거 기록 의무** 하나입니다. 이 장치가
충분하다는 증거는 없습니다 — 회차가 쌓이면 편성 편향을 사후 점검해야 합니다(§5 미해결).

### 2.3 `T0` 자동 종결의 안전장치

사용자가 저위험 자동 종결을 선택했으므로, "합의=검증" 오류에 대한 노출을 네 가지로 제한했습니다.

1. 화이트리스트 열거 (목록에 없으면 `T0` 아님)
2. `R` 좌석의 **명시적 무반박 기록** — 침묵은 동의로 치지 않음
3. 되돌릴 수 있을 것
4. **단일 좌석 거부권** — 어느 좌석이든 이의 제기 시 즉시 `T1` 승격

### 2.4 실측 근거를 반영한 실패 규정

같은 계열 구조(다른 저장소의 7좌석 협의체)에서 관측된 실패를 규범에 넣었습니다.
좌석당 토큰 상한 `32000` 하한선, `finish_reason` 확인 의무, 빈 응답의 **기권** 처리와
공백 명시, `P`/`S` 좌석 실패 시 **회차 무효**, 시작 전 좌석별 확인 질의.

> 이 수치는 **다른 저장소·다른 모델 구성에서의 관측**입니다. ICF 좌석 구성에서 재확인하지
> 않았으므로, 하한선으로만 쓰고 ICF 실측으로 대체해야 합니다.

### 2.5 한계의 명문화

"같은 모델의 좌석 여럿은 독립 표본이 아니다", "표결을 증거로 쓰지 않는다",
"좌석 수를 진척으로 쓰지 않는다"를 §3에 명시했습니다. 좌석을 늘려도 증거는 세지지 않습니다.

## 3. 고려했으나 기각한 대안

- **기존 5역할 유지 + 토론 계층 추가**: 기존 문서·결정 이력과의 충돌이 가장 적으나,
  §2-2 금지 조문과 1:1 세션 고정이 그대로 남아 협의체가 규범 예외로만 존재하게 됩니다.
  사용자가 근본 재편을 선택했습니다.
- **토론을 Idea 생성 단계로 한정**: 안전하지만 반증·감사 좌석의 가치를 쓰지 못합니다.
- **고정 로스터**: 회차 간 비교가 쉬우나 질문 성격과 무관하게 같은 비용이 듭니다.
- **모든 종결을 사용자에게**: 가장 보수적이나 사용자 부하가 큽니다.

## 5. 미해결

- **협의체 실행 인프라가 없습니다.** 규범만 확정됐고 좌석을 실제로 소집하는 수단이 ICF에
  없습니다. 다른 저장소의 선행 구현을 이식할지, 새로 만들지 미정입니다.
- **좌석→엔드포인트 배정 정책 미정**: 현재 로컬 서버 4개가 가동 중이나, ICF 좌석 수·동시성
  상한과의 매핑 규칙을 정하지 않았습니다.
- **`T0` 화이트리스트가 충분한지 미검증**입니다. 실제 회차에서 경계 사례를 만나면
  목록을 조정해야 하며, 조정은 `T2`(사용자 결정)입니다.
- **편성 편향의 사후 점검 방법 미정**(§2.2).
- 이 RFC 자체가 **단일 주체의 산출물**이며 다자 검토를 거치지 않았습니다.
