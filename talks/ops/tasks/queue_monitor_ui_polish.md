# 딥시크 큐 모니터 UI 간소화

사용자 피드백에 따라 현재 `scripts/ops/queue_monitor.py`의 화면 구성을 간소화하라.
모니터링 데이터 수집과 상태 머신은 유지하고, 아래 표시 요구를 구현·테스트하라.

## 요구사항

1. 화면 최상단 서버 지표에서 `처리 중`, `대기 중`, `KV 캐시` 카드를 제거한다.
   최상단에는 `초당 생성`과 `오늘 생성 토큰` 두 카드만 남긴다.
2. 오늘 생성 토큰의 화면 기준은 당일 자정(`00:00 KST`)이다. 화면에서
   `자정~관측 시작 구간 미포함`, `관측 시작`, `서버 재시작 이후만 집계` 같은 설명은
   전부 제거한다. 단, 내부 rollover/reset 계측과 `모름` 처리는 훼손하지 않는다.
3. 두 카드 아래에 표시되는 vLLM endpoint 주소를 제거한다. API 내부 URL 필드는 기존
   호환성이 필요하면 유지해도 되지만 HTML에는 출력하지 않는다.
4. 현재 `work-starved` 경고를 별도 큰 블록으로 두지 말고, 페이지 맨 위
   `딥시크 큐 모니터` 제목 바로 옆에 작은 경고 배지로 표시한다. 정상 상태에서는
   불필요한 설명을 붙이지 않는다. 서버 도달 불가 같은 실제 경고도 제목 옆 상태로
   일관되게 나타낼 수 있는지 검토해 구현한다.
5. GPU 영역에서 부가 설명을 모두 제거한다. 섹션 제목의 원격 호스트·캐시 설명,
   전력 한도 열, 출처, 수집 시각, exporter 안내를 화면에서 없애고 다음 세 열만 남긴다.
   - 전력 사용
   - 가동률
   - 상태
6. GPU 상태는 값 존재 여부만으로 `정상`이라고 쓰지 않는다.
   - 가동률이 연속 10초 이상 `0%`일 때 `유휴`로 표시한다.
   - 10초 미만의 0% 표본은 아직 유휴로 확정하지 않는다.
   - 가동률이 0보다 크면 `사용 중`으로 표시한다.
   - telemetry 누락·오래됨·도달 불가는 `모름` 또는 `도달 불가`로 표시하며 0으로
     대체하지 않는다.
   연속 0% 판정은 브라우저의 단일 렌더 시각이 아니라 수집 시각/캐시된 상태에 근거해야
   하며, 새로고침만으로 유휴 시간이 거짓 증가하지 않아야 한다.
7. `딥시크가 할 일` 영역에 vLLM의 `처리 중`·`대기 중` 숫자를 옮겨 표시한다.
   그 아래에는 기존처럼 실제 `running`/`pending` 작업 제목·상태·요약을 보여준다.
   작업이 없더라도 두 숫자는 보이게 한다.

## 변경 범위와 보호 조건

- 주 변경 대상: `scripts/ops/queue_monitor.py`, `scripts/ops/gpu_telemetry.py`,
  `tests/test_queue_monitor.py`.
- 필요하면 운영 보고서만 함께 갱신한다.
- `AGENTS.md`, 연구 결과, RU 문서, 모델·평가 코드는 수정하지 않는다.
- 외부 Python 의존성을 추가하지 않는다.
- 주소·토큰·SSH 설정을 새로 하드코딩하지 않는다.

## 완료 조건

1. HTML 문자열 수준에서 제거 대상 문구와 열이 사라졌는지 테스트한다.
2. GPU 0%가 10초 미만이면 유휴가 아니고, 10초 이상 연속이면 `유휴`, 양수이면
   `사용 중`이 되는 순수 함수 테스트를 추가한다.
3. telemetry 누락·stale·실패가 `유휴`로 오인되지 않는 테스트를 추가한다.
4. 처리 중·대기 중 숫자가 최상단 카드에는 없고 `딥시크가 할 일` 영역에 있는지 테스트한다.
5. 관련 ops 테스트와 `git diff --check`를 실행하고, 마지막 출력에 브랜치·변경 파일·
   테스트 결과·남은 위험을 적는다.

빠르게 구현하되, 한 번의 0% 표본을 10초 유휴로 꾸며내지 마라.
